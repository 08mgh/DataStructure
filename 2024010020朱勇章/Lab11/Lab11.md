## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无（顺序执行：逐个 `new` 出 6 个节点并连接 `lc`/`rc`） | 不输出任何内容 | 无 |
| `preorder()` | `root == nullptr` 时直接返回 | 进入左、右子树递归**之前**（根 → 左 → 右） | 无（递归栈由系统维护） |
| `inorder()` | `root == nullptr` 时直接返回 | 左子树递归返回后、进入右子树递归**之前**（左 → 根 → 右） | 无（递归栈由系统维护） |
| `postorder()` | `root == nullptr` 时直接返回 | 左、右子树递归均返回**之后**（左 → 右 → 根） | 无（递归栈由系统维护） |
| `levelOrder()` | `root == nullptr` 时直接返回（空树判断，非递归） | 节点**出队**时 | `std::queue<Node*>` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种遍历都把二叉树拆成"根、左子树、右子树"三部分，递归结构完全相同，唯一的区别是"访问根"（输出语句）放在两次递归调用的前、中、后哪个位置。若去掉这句，三个函数体就完全一样了——都只是按"左子树、右子树"的顺序空跑递归，输出完全相同，三个函数之间不再有任何区别。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造函数保证每个新节点创建后 `lc`、`rc` 都是 `nullptr`，叶子节点不必再逐个显式置空就能正确表示"没有孩子"，遍历遇到 `nullptr` 即可安全返回。若两个孩子是未初始化的随机值，遍历到叶子后会沿着随机指针继续访问非法内存，导致程序崩溃或输出乱码；层次遍历中 `p->lc != nullptr` 的孩子入队检查也会失效，把随机地址当孩子入队，进一步扩大错误。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 因为一旦先释放根节点，就无法再通过根指针访问它的左右子树，递归释放子树时会产生悬垂指针（访问已释放内存的未定义行为），还会造成子树内存泄漏。按"先左右子树、后根"释放正好对应**后序遍历**（左 → 右 → 根）。若先 `delete` 根再递归释放子树，后续递归要读取 `root->lc`、`root->rc`，此时 root 已被释放，程序会崩溃或产生未定义行为。

### 6.2 手工追踪四种遍历

对课堂演示的满二叉树（`A` 的左、右孩子是 `B`、`C`；`B` 的左、右孩子是 `D`、`E`；`C` 的左、右孩子是 `F`、`G`），**不看程序输出**，在草稿纸上推演后填写各序列（字符间用空格分隔）：

| 遍历 | 序列 |
| :--- | :--- |
| 先序 | A B D E C F G |
| 中序 | D B E A F C G |
| 后序 | D E B F G C A |
| 层次 | A B C D E F G |

再对本次作业指定的树（`C` 只有右孩子 `F`，共 6 个节点）推演四种序列，与 5.3 的程序输出对照。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序遍历是"左 → 根 → 右"，总是先处理左子树，所以整棵树**最左**的节点最先被访问。从根 `A` 出发沿 `lc` 指针一路向左下：`A->lc = B`，再 `B->lc = D`；`D` 是叶子（`lc`、`rc` 均为 `nullptr`），没有左子树，因此它就是中序序列的第一个节点。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左的单链树（`A`→`B`→`C` 全走 `lc`）：先序 `A B C`，中序 `C B A`，后序 `C B A`，层次 `A B C`——**中序与后序相同**（都是 `C B A`）。因为中序"左根右"和后序"左右根"都先把左子树（整条链）处理完才轮到根，而树上除根外每个节点恰好是上一节点的左子树，所以两者都得到从最深的 `C` 到根 `A` 的倒序。向右的单链树（全走 `rc`）：先序 `A B C`，中序 `A B C`，后序 `C B A`，层次 `A B C`——**先序与中序相同**（都是 `A B C`）。因为先序"根左右"和中序"左根右"里，每次"左子树"都为空，都是先访问当前根再走向右子树，所以两者都得到从根 `A` 到最深 `C` 的正序。

3. 满二叉树的手工推演与课堂演示 `BinTreeTraversal.cpp` 的输出是否一致？指定树的推演与自己程序的输出是否一致？如有出入，错在哪里？

   > 一致。满二叉树（`A` 的左右孩子 `B`、`C`，`B` 的左右孩子 `D`、`E`，`C` 的左右孩子 `F`、`G`）手工推演：先序 `A B D E C F G`、中序 `D B E A F C G`、后序 `D E B F G C A`、层次 `A B C D E F G`；指定树（`C` 只有右孩子 `F`）手工推演：先序 `A B D E C F`、中序 `D B E A C F`、后序 `D E B F C A`、层次 `A B C D E F`。两者都与对应程序输出逐行一致。若出现出入，应先检查建树时 `lc`/`rc` 指针是否连错（如把 `C` 的左孩子误连到别处），再检查遍历函数的递归顺序。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰好被"访问"（输出）一次，空指针调用为常数开销，总次数 2n+1 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h)，最坏 O(n) | 递归深度等于树高 h：空树为 0、单节点树为 1；单链树深度达 n，平衡树约 log₂n |
| 层次遍历的时间 | O(n) | 每个节点恰好入队一次、出队一次，其余判断为常数开销 |
| 层次遍历的辅助空间（队列） | O(w)，最坏 O(n) | 队列同时最多容纳一层节点，最大为树宽 w；满二叉树最后一层约 n/2 个节点 |
| `main` 中手动创建 6 个节点的时间 | O(1) | 固定创建 6 个节点并连接指针，与 n 无关的常数操作 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。递归深度达到 n 的树是**单链树**（每个节点至多一个孩子，如全左链或全右链，一路递归到底）；队列长度达到 n 的树是**最宽层节点数为 n 的树**，例如满二叉树——其最后一层（最大宽度层）就有约 n/2 个节点同时入队，若树本身只有两层且第二层节点数为 n-1，队列长度同样接近 n。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后，得到**后序遍历**（左 → 右 → 根）；移到两次递归中间（左子树递归与右子树递归之间），得到**中序遍历**（左 → 根 → 右）。这正是三种递归遍历只差"访问根"语句位置的原因。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求"从上到下、从左到右"逐层访问，队列的先进先出（FIFO）特性保证：父节点先入队先出队，同一层的节点按从左到右的顺序依次出队，上一层全部处理完下一层才轮到，从而维持层序。若换成栈（LIFO），出队顺序被反转成"后进先出"，不再按层推进，输出会变成**深度优先**的特点——从根出发沿一条路径（通常是右孩子先入栈则先走左路）一路访问到最深处，再回溯访问其他分支，类似先序但左右子树的相对顺序会随入栈顺序改变，无法得到正确的层次序列。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当树的每一层都只有一个节点（即树退化成**单链**）时，先序与层次序列相同。因为此时"深度优先先走到最深"与"逐层访问"的次序完全重合。例如右单链树 `A->rc = B`、`B->rc = C`：先序 `A B C`，层次 `A B C`，两序列相同；再如左单链树 `A->lc = B`、`B->lc = C`：先序 `A B C`，层次 `A B C`，也相同。而满二叉树先序 `A B D E C F G` 与层次 `A B C D E F G` 就不相同。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序 + 中序**能**唯一确定二叉树：先序的第一个元素是根，在中序中找到它即可把左右子树的中序序列分开，再按先序中剩余的次序递归确定左右子树的根，逐层还原。例如先序 `A B C`、中序 `C B A`：根是 `A`，中序中 `A` 左边是 `C B`（左子树），右边为空，故 `A` 无右子树；左子树先序为 `B C`，根是 `B`，中序 `C B` 中 `B` 左边是 `C`，即 `B->lc = C`，唯一确定这棵树。只给先序序列则**不能**唯一确定：先序 `A B C` 可以是左单链（`A->lc=B, B->lc=C`）、右单链（`A->rc=B, B->rc=C`）、`A` 左孩子 `B` 右孩子 `C` 等多种形状，所以仅凭先序无法确定树形。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 我的实现用 `new Node('A')` 一行完成"创建+赋值"，6 个节点共 6 行，加上 13 行 `lc`/`rc` 指针连接和 1 行 `root = A`，建树部分约 20 行代码。对 1000 个节点，逐个手动 `new` 并手工连线完全不现实：代码量爆炸、极易连错指针、无法维护。同样的元素按不同形状组织，查找代价差异很大（单链树查找 O(n)，平衡树 O(log n)），说明树形决定了操作效率。下一阶段应学习**二叉搜索树（BST）**及平衡化结构（如 AVL 树、红黑树）：利用元素的有序性，通过插入操作自动建树，并保持树高平衡，使查找、插入、删除都达到 O(log n)。
