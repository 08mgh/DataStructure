## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务

- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 不递归，无递归出口；前提是按树形图逐个 `new` 节点，再按父子关系连接 `lc` / `rc` | 全程不输出，建树部分不含任何 `cout` | 无，只用到 6 个节点指针和根指针 `root` |
| `preorder()` | `root == nullptr` 时直接返回 | 进入函数后、两次递归之前（先访问根） | 无，只有系统管理的递归调用栈 |
| `inorder()` | `root == nullptr` 时直接返回 | 左子树递归返回之后、右子树递归之前（两次递归中间访问根） | 无，只有系统管理的递归调用栈 |
| `postorder()` | `root == nullptr` 时直接返回 | 左右两次递归都返回之后（最后访问根） | 无，只有系统管理的递归调用栈 |
| `levelOrder()` | `root == nullptr` 时直接返回；此外要求队列非空才出队 | 节点出队时（出队即访问） | `std::queue<Node*>` 队列 |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种遍历都是把二叉树拆成"根、左子树、右子树"三部分，递归骨架完全相同：先判断是否为空树，再对左子树、右子树各递归一次。它们唯一的差别就是"输出根节点"这一句放在两次递归之前、之间还是之后，这正好对应先序、中序、后序的定义。如果把访问根的语句去掉，三个函数体就逐字相同了（都只剩递归出口和两次递归调用），对任意形状的树都不产生任何输出，三者再无区别，也就无法再区分先序、中序和后序。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造把 `lc`、`rc` 置为 `nullptr`，保证每个 `new` 出来的节点一开始就是"叶子"：所有尚未显式连接的位置（各叶子节点、以及 `C` 的左孩子）都是空指针，树的形状完全由随后赋值的指针决定，遍历时判空就能安全跳过。如果孩子指针是随机值（野指针），四种遍历就会顺着不属于这棵树的地址往下走：轻则输出多余字符、序列错乱，重则访问非法内存直接崩溃；层次遍历还会把这些随机地址继续入队扩散，最后 `destroyTree` 对无效指针执行 `delete` 更是未定义行为。即使侥幸没有崩溃，遍历结果也已毫无意义。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 节点被 `delete` 之后，它自己的 `lc`、`rc` 成员也随之失效。若先释放根，就再也无法沿着这两个指针找到并释放两棵子树，造成大面积内存泄漏；若释放后仍通过旧指针递归，则属于 use-after-free（释放后使用），是未定义行为，可能直接崩溃。所以必须先把左、右子树都释放完，最后才释放根。"先左右子树、后根"与后序遍历（左-右-根）的顺序完全一致，`destroyTree` 本质上就是一次不输出的后序遍历。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序遍历必须先把整棵左子树处理完才访问根，因此总是先一路向左走到最左下角的节点。从根出发沿左孩子指针下降：`root` 即 `A`，`A->lc` 是 `B`，`B->lc` 是 `D`，而 `D->lc` 为空，不能再向左，于是第一个被访问的就是 `D`。这条路径沿三次 `lc` 指针（`root -> A -> B -> D`）；访问 `D` 后回溯输出 `B`，再进入 `B` 的右子树输出 `E`。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左单链（`A ->lc B ->lc C`）：中序与后序相同，都是 `C B A`。每个节点都没有右孩子，"向右"的递归立即返回；先序先访问根再进左子树，得到 `A B C`，而中序、后序都要先处理完左子树才访问根，于是都变成从最深的左孩子往根回溯，序列同为 `C B A`（此时先序与层次遍历也恰好相同，都是 `A B C`）。
   >
   > 向右单链（`A ->rc B ->rc C`）：先序与中序相同，都是 `A B C`。每个节点都没有左孩子，中序的"先左"立即返回，访问根之后只能向右，这与先序"根之后立刻向右"的走法完全重合；层次遍历每层只有一个节点，从上到下也正是 `A B C`，所以三者相同。只有后序最后访问根，得到 `C B A`。

- 对有 `n` 个节点的二叉树执行一次先序遍历，`preorder` 一共被调用多少次（含空树调用）？共 `2n+1` 次：`n` 个真实节点各被调用一次，另有两类空孩子指针共 `n+1` 个，每个对应一次空树调用，所以是 `n + (n+1) = 2n+1`（本表 `n = 3`，正好 7 次）

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | Θ(n) | 每个节点恰好被访问并输出一次，每条树边被递归经过两次，单次操作是常数时间，总代价与节点数成正比 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h)，最坏 Θ(n) | 只用递归调用栈：任意时刻栈中保存从根到当前节点的一条路径，深度等于树高 `h`；空树 `h = 0`，单节点树 `h = 1` |
| 层次遍历的时间 | Θ(n) | 每个节点入队、出队各一次并输出一次，队列的 `push` / `front` / `pop` / `empty` 都是常数开销，总计线性 |
| 层次遍历的辅助空间（队列） | O(w)，最坏 Θ(n) | 队列中只存放尚未访问的已入队节点，最多是当前层剩余节点加上已出队节点的孩子，数量由最大宽度 `w` 决定；空树不建队列，单节点树队列最长为 1 |
| `main` 中手动创建 6 个节点的时间 | Θ(1)（常数） | 6 是固定常数：`new` 6 次、孩子指针赋值 12 次、根指针赋值 1 次，都是固定次数的常数操作；若推广到建 `n` 个节点，则为 Θ(n) |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。

`O(h)` 能解释边界情况：空树调用一次就返回，栈深为 0；单节点树 `h = 1`，栈深为 1。当树退化成单支链（每个非叶节点只有一个孩子，例如一路只有左孩子或一路只有右孩子）时 `h = n`，递归深度达到 `n`，递归栈退化为 `O(n)`。

`O(w)` 同理：空树不入队，单节点树队列中同时最多只有 1 个节点；当树是满二叉树（或最后一层很宽的完全二叉树）时，最后一层节点数约为 `(n+1)/2`，在开始出队访问最后一层之前，这些节点全都排在队列里，队列长度达到 `Θ(n)` 量级。对任意二叉树，队列长度都不会超过 `(n+1)/2`，但仍与 `n` 同阶，所以记作 `O(w)`、最坏 `Θ(n)`。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后，"左、右子树都处理完才访问根"，得到的是后序遍历；移到两次递归中间，"左子树 -> 根 -> 右子树"，得到的是中序遍历。也就是说三种遍历的差别只是这一行语句的位置。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求"先被访问的节点，其孩子要排在后被访问节点的孩子之后"，即上一层全部访问完才轮到下一层，同一层内从左到右。队列先进先出正好满足这一点：父节点出队访问后，把左、右孩子依次放到队尾，它们自然排在同层尚未出队的节点之后、下一层之前。若换成栈（后进先出），刚入栈的孩子会马上被取出，遍历变成深度优先：以本次的树为例，`A` 出栈后压入 `B`、`C`，接着弹出的是 `C`，输出变为 `A C F B E D`，相当于"根-右-左"的先序，节点不再按层相邻，也就不是层次遍历了。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 两者相同的前提是：先序在某个节点之后"向下深入"的顺序，恰好等于层次遍历"同层从左到右"的顺序。典型情况有两种：一是树退化成单支链，每层只有一个节点，例如向右单链 `A ->rc B ->rc C`，先序和层次都是 `A B C`；二是每个同时有左、右孩子的节点，其左孩子都是叶子（这样先序访问完根和左孩子后，正好轮到右兄弟），例如三节点的 `A`（左 `B`、右 `C`，`B`、`C` 都是叶子），先序和层次都是 `A B C`。
   >
   > 一旦某个节点的左子树不止一个节点，先序会先深入左子树，而层次遍历要先把同层的右兄弟访问完，两者随即分开。例如本次 6 节点树：先序 `A B D E C F`，层次 `A B C D E F`。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序加中序可以唯一确定。先序的第一个元素就是根；在中序中找到它，左边是左子树的中序、右边是右子树的中序；再按左子树的节点个数把先序中根之后的部分切成左、右两段，递归即可还原整棵树。以本次的树为例：先序 `A B D E C F`、中序 `D B E A C F`，根为 `A`，中序左边 `D B E`（3 个节点）对应先序的 `B D E`，右边 `C F` 对应 `C F`；对 `B D E` 继续：根 `B`，中序 `D | B | E`，得 `B` 的左孩子 `D`、右孩子 `E`；对 `C F`：根 `C`，中序 `C | F`，左子树为空，`F` 是 `C` 的右孩子。结果正是本次这棵树，且唯一。
   >
   > 只给先序序列则不能唯一确定。例如先序 `A B C` 可以对应 `A` 的左孩子 `B`、右孩子 `C`（两棵子树），也可以对应 `A` 的左孩子 `B`、`B` 的右孩子 `C`，还可以对应 `A` 的右孩子 `B`、`B` 的右孩子 `C`，先序无法说明某个节点到底挂在哪一侧、以什么层次连接；甚至 `A B`（两个节点）也有 `B` 是 `A` 的左孩子还是右孩子两种可能。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 我为 6 个节点写了 `new` 6 行、给孩子指针赋值 12 行、根指针赋值 1 行，共 19 行（不含空行和注释）。若是 1000 个节点，约需 1000 行 `new` 加约 2000 行指针赋值，三千行代码几乎无法正确维护：既容易把指针连错，也无法在运行时按数据自动决定树形，完全不现实。而且同样的元素按不同形状组织，查找效率差别很大——单支链退化成链表要比较 `n` 次，而较平衡的树只需约 `log n` 次。要高效地建树和查找，下一阶段应学习按关键字自动组织形状的二叉搜索树（BST）及其平衡化（如 AVL 树），以及散列等结构。
