## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务

- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无（main 直接顺序执行） | 建树阶段只 new、赋 data、连 lc/rc，不输出；输出由四种遍历函数完成 | 无（逐个 new 节点并用指针连接） |
| `preorder()` | 空树（`root == nullptr`）直接返回 | 访问根在递归左、右子树之前 | 无（靠系统递归调用栈） |
| `inorder()` | 空树直接返回 | 访问根在递归左子树之后、递归右子树之前 | 无（靠系统递归调用栈） |
| `postorder()` | 空树直接返回 | 访问根在递归左、右子树之后 | 无（靠系统递归调用栈） |
| `levelOrder()` | 空树直接返回，否则根入队 | 出队时访问该节点（同层从左到右、上层先于下层） | `std::queue<Node*>` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

> 因为三种递归遍历的主体结构完全相同：都是「空树返回 + 访问根 + 递归左子树 + 递归右子树」四部分，唯一区别只是「访问根」这条语句在两次递归调用之间的位置（最前、中间、最后）。如果把访问语句去掉，三个函数的剩余代码完全一样——都变成空树返回后再依次递归左、右子树，行为完全一致，没有任何区别，因为驱动遍历的骨架（递归进入左右子树）是相同的。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

> 默认构造把 lc、rc 置为 nullptr，保证每个新节点初始都是孤立的叶子，树形完全由后续显式的 lc/rc 赋值决定，不会残留垃圾指针。如果两个孩子是随机值：三种递归遍历沿 lc/rc 递归时会访问野指针，轻则读到垃圾地址继续越界递归，重则直接段错误崩溃；层次遍历把野指针入队后 front/pop 访问同样崩溃；destroyTree 还会对野指针 delete，造成非法释放或 double free。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

> destroyTree 先递归释放左、右子树，最后才 delete 根，正好对应后序遍历的顺序（左-右-根）：只有两个孩子都已释放，根才能安全删除。若先 delete 根，再递归释放子树时需要通过 root->lc / root->rc 访问已经被 delete 的内存（悬垂指针），读到已回收的堆数据是未定义行为——轻则拿到垃圾指针继续递归或崩溃，重则对同一内存重复释放；所以必须自底向上、最后删根。

### 6.2 手工追踪四种遍历

| 遍历 | 序列 |
| :--- | :--- |
| 先序 | A B D E C F G |
| 中序 | D B E A F C G |
| 后序 | D E B F G C A |
| 层次 | A B C D E F G |

再对本次作业指定的树（`C` 只有右孩子 `F`，共 6 个节点）推演四种序列，与 5.3 的程序输出对照。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

> 中序是「左-根-右」，序列的第一个节点是整棵树最左下、没有左孩子的节点。从根 A 出发沿 lc 指针一直下降：A->lc = B，B->lc = D，D 的 lc 为 nullptr，所以 D 没有左子树，中序最先访问 D。也就是沿着「左孩子指针链」一路下降到 lc 为空的那个节点。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

> 向左单链（A 左 B，B 左 C）：中序与后序相同，都是 C B A。原因：每个节点只有左孩子、右子树为空，中序「左-根-右」退化为「左递归-根」，后序「左-右-根」退化为「左递归-根」，两者都变成从最深的 C 开始逐层输出。向右单链（A 右 B，B 右 C）：先序与中序相同，都是 A B C。原因：每个节点左子树为空，先序「根-左-右」退化为「根-右递归」，中序「左-根-右」退化为「根-右递归」，都从根开始逐层向下输出。

### 6.3 手工展开递归调用

对只有三个节点的树 `A`（左孩子 `B`、右孩子 `C`）执行 `preorder(A)`。前两次调用已填好作示范，完成全表（空树调用也是一行）：

| 调用顺序 | 当前调用 | 动作 |
| :---: | :--- | :--- |
| 1 | `preorder(A)` | 输出 `A`，进入左子树 |
| 2 | `preorder(B)` | 输出 `B`，进入左子树 |
| 3 | `preorder(nullptr)`（B 的左子树） | 空树直接返回 |
| 4 | `preorder(nullptr)`（B 的右子树） | 空树直接返回 |
| 5 | `preorder(C)` | 输出 `C`，进入左子树 |
| 6 | `preorder(nullptr)`（C 的左子树） | 空树直接返回 |
| 7 | `preorder(nullptr)`（C 的右子树） | 空树直接返回 |

- 这 7 次调用中有 4 次是「空树直接返回」（第 3、4、6、7 次）。
- 对有 `n` 个节点的二叉树执行一次先序遍历，`preorder` 一共被调用 2n+1 次（含空树调用）：n 个节点各调用一次，加上每个空孩子指针各触发一次空树调用——n 个节点的二叉树恰有 n+1 个空指针，故总次数 = n + (n+1) = 2n+1。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰好被访问一次，每次访问与两次递归调用均为常数工作 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h) | 递归深度等于树高 h，同时最多占用 h+1 层调用栈；空树 0、单节点树 1 |
| 层次遍历的时间 | O(n) | 每个节点入队一次、出队一次，各为常数工作 |
| 层次遍历的辅助空间（队列） | O(w) | 队列中同时存放的节点数不超过某一层的节点数，最大即树的宽度 w；空树 0、单节点树 1 |
| `main` 中手动创建 6 个节点的时间 | O(1) | 固定 6 次 new、6 次 data 赋值与若干次 lc/rc 赋值，不随输入规模增长 |

说明：递归深度达到 `n` 的形状是单链树（每层只有一个节点，如全左或全右单链），此时 h = n，递归栈占用 O(n)；队列长度达到 `n` 的形状是底层最宽的近完全二叉树/满二叉树（最后一层约 n/2 个节点，整层最大宽度约 n/2，仍为 O(n)），此时 w 与 n 同阶。空树时递归深度和队列长度都是 0，单节点树都是 1，以上表达式均能解释。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

> 把「访问根」移到两次递归之后，得到后序遍历（左-右-根）：先递归处理完左、右子树，最后才输出根。移到两次递归中间，得到中序遍历（左-根-右）：递归左子树结束后输出根，再递归右子树。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

> 层次遍历必须用队列：它要求「先被访问的节点，其孩子先被访问」，即先进先出——第 k 层的节点先入队，全部出队访问完后，第 k+1 层才按从左到右到达队头。若换成栈（后进先出），孩子节点后入先出，访问顺序变成沿一条路径深度优先推进：以满二叉树为例，先压右孩子再压左孩子时输出 A B D E C F G，与先序遍历完全相同，同层从左到右的顺序被破坏，不再是「从上到下、从左到右」。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

> 先序与层次相同当且仅当树的每一层至多一个节点，即整棵树退化为单链（每层只有一个节点，唯一的路径就是访问顺序）。例如向左单链 A(B(C))：层次为 A B C，先序也是 A B C，两者相同；向右单链 A→B→C 同样都是 A B C。而满二叉树 A(B(D,E),C(F,G)) 层次为 A B C D E F G，先序为 A B D E C F G，两者不同——因为第二层有两个节点，层次先访问完 B、C 才到第三层，先序却会先深入 B 的左子树。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

> 先序+中序能唯一确定二叉树：先序的第一个元素是根，在中序中找到根的位置，其左边是左子树的中序、右边是右子树的中序，再按先序的剩余部分递归划分。例如先序 A B D C、中序 B D A C：根是 A，中序左子树 B D、右子树 C；先序剩余 B D C 中 B 是左子树根，中序 B D 中 B 在前，说明 D 是 B 的右孩子，树形唯一确定。只给先序不能唯一确定：先序 A B 既可以是 A 的左孩子是 B，也可以是 A 的右孩子是 B，两种形状不同的树先序序列相同。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

> 用带元素构造函数写法约 12 行（6 个 new + 6 组 lc/rc 赋值，再加显式置空），用默认构造再赋值约 20 行。1000 个节点逐条手写完全不现实——行数随节点数线性爆炸且极易连错指针。同样的元素集合，组织成平衡结构查找是 O(log n)，组织成单链则退化为 O(n)，差异巨大。下一阶段应学习二叉搜索树/平衡二叉树（BST、AVL 树等）：在建树和插入时自动维护有序与平衡，使查找、插入都保持在 O(log n)，并用遍历序列或逐层读入的方式自动建树，不再手工 new 每个节点。
