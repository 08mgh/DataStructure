## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归出口，是一串顺序语句 | 每个节点 `new` 出来时立即用 `data` 赋值 | 无，只用到节点指针 |
| `preorder()` | `root == nullptr` 时直接返回 | 在两次递归**之前**访问根 | 递归调用栈 |
| `inorder()` | `root == nullptr` 时直接返回 | 先递归左子树、再访问根、最后递归右子树 | 递归调用栈 |
| `postorder()` | `root == nullptr` 时直接返回 | 在两次递归**之后**访问根 | 递归调用栈 |
| `levelOrder()` | `root == nullptr` 时直接返回 | 每次从队头取出一个节点时访问 | `std::queue<Node*>`（先进先出队列） |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种遍历都要完整走进每个节点并递归其左、右子树，处理"根、左子树、右子树"这三部分的动作完全相同，唯一的差别就是把"访问根"（输出 `data`）这一句放在两次递归之前、之间还是之后。如果把这句去掉，三个函数就只剩"空树返回 + 两次递归"的骨架，先后顺序完全一样，彼此不再有任何区别。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造把 `lc`、`rc` 置为 `nullptr`，使叶子节点和"缺失的孩子"天然为空指针，正是递归出口 `root == nullptr` 成立的基础，建树时只需给真正的孩子赋指针即可。若 `new` 出来的节点孩子是随机值，遍历就会顺着野指针走到不属于本树、甚至未映射的内存，轻则多输出字符，重则直接崩溃（未定义行为），三种递归遍历和层次遍历都会出错。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 必须先释放完左右子树、最后才 `delete` 根，否则删掉根后 `root->lc`、`root->rc` 随对象一起失效，再去用它们递归就是访问已释放内存。这个"左-右-根"的顺序与**后序遍历**一致。若先 `delete` 根再递归子树，递归时读到的已是释放后的悬挂指针，属于未定义行为，通常会崩溃或造成内存错误。

### 6.2 手工追踪四种遍历

对课堂演示的满二叉树（`A` 的左、右孩子是 `B`、`C`；`B` 的左、右孩子是 `D`、`E`；`C` 的左、右孩子是 `F`、`G`），**不看程序输出**，在草稿纸上推演后填写各序列（字符间用空格分隔）：

| 遍历 | 序列 |
| :--- | :--- |
| 先序 | A B D E C F G |
| 中序 | D B E A F C G |
| 后序 | D E B F G C A |
| 层次 | A B C D E F G |

再对本次作业指定的树（`C` 只有右孩子 `F`，共 6 个节点）推演四种序列，与 5.3 的程序输出对照。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序是"左-根-右"，只有某节点的左子树全部处理完才会访问它，所以第一个被访问的必是最靠左、且没有左孩子的节点。从根 `A` 出发沿左孩子指针 `A->lc` 到 `B`，再沿 `B->lc` 到 `D`；`D` 没有左孩子，于是 `D` 最先被访问。这条下降路径就是 `A->lc`、`B->lc`。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左的单链树里**中序和后序**相同，都是 `C B A`：没有右子树，中序沿左链下到底后回退访问根，postorder 先递归左子树（到底后先访问 `C`）再访问根，回退顺序一致。向右的单链树里**先序和中序**相同，都是 `A B C`：没有左子树，先序访问根后立即进右子树，中序也是先访问根再进右子树，两者访问顺序相同。

3. 满二叉树的手工推演与课堂演示 `BinTreeTraversal.cpp` 的输出是否一致？指定树的推演与自己程序的输出是否一致？如有出入，错在哪里？

   > 一致。满二叉树手工推演的四种序列（先序 `A B D E C F G`、中序 `D B E A F C G`、后序 `D E B F G C A`、层次 `A B C D E F G`）与课堂演示输出相同；本次指定树手工推演（先序 `A B D E C F`、中序 `D B E A C F`、后序 `D E B F C A`、层次 `A B C D E F`）与自己程序的四行输出也逐行一致，没有出入。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰被访问（输出）一次，每次调用还发起两次子递归，总调用 2n+1 次，每次都是常数开销 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h) | 递归深度等于树高 h，栈上最多同时保留 h 层调用；空树 h=0、单节点 h=1（都为 O(1)），最坏是单链树 h=n |
| 层次遍历的时间 | O(n) | 每个节点入队、出队、访问各一次，均为常数开销，总时间与节点数成正比 |
| 层次遍历的辅助空间（队列） | O(w) | 队列在同一时刻最多存放一层的节点，即最大宽度 w；空树队列为空、单节点树 w=1（都为 O(1)），最坏时 w 可达 O(n) |
| `main` 中手动创建 6 个节点的时间 | O(n)，本题 n=6 | 每个节点各 `new`、赋值、连指针一次，工作量与节点数成正比（本题即常数的 6 次） |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。空树时 h=0、w=0，单节点树 h=1、w=1，都在 O(1) 范围内，所以 O(h)、O(w) 能覆盖这两种边界。**单链树**（每个节点只有一个孩子，无论全左还是全右）会让树高 h=n，递归深度达到 n；**完全二叉树**（尤其最后一层节点最多）会使最大宽度 w 达到约 n/2，即 O(n)，此时队列长度最大。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后，访问根的时机变成"左、右、根"，得到**后序遍历**；移到两次递归中间，访问时机变成"左、根、右"，得到**中序遍历**。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求同一层的节点按从左到右、且第 k 层全部处理完后才处理第 k+1 层，这正需要"先来先访问"的先进先出顺序，队列的 `push`/`front`/`pop` 恰好保证这一点。若换成栈（后进先出），同一层压入的节点会被后压入的先取出，左右顺序颠倒，并优先深入更深一层，得到的是类似深度优先、且左右乱序的序列，无法再"从上到下、从左到右"。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当二叉树是一条**单链**（每个节点至多一个孩子，即每一层只有一个节点）时两者相同：例如 `A` 的左孩子是 `B`、`B` 的左孩子是 `C`，先序是 `A B C`，层次也是 `A B C`。而一旦同一层出现多个节点就不同，例如满二叉树先序是 `A B D E C F G`、层次是 `A B C D E F G`，可见只有当每一层只剩一个节点（链状）时两个序列才重合。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 能。先序的第一个元素就是根，在中序里定位它即可把中序分成左、右两段（左子树的节点集合、右子树的节点集合），再据各段长度切出先序中的左右子树、递归重建。例如先序 `A B D E C F`、中序 `D B E A C F`：根是 `A`，中序中 `A` 左边 `D B E` 是左子树、右边 `C F` 是右子树，唯一确定本次这棵树。只给先序则不能唯一确定：先序 `A B C` 既可能是"A 为根、B 为左孩子、C 为 B 的左孩子"，也可能是"A 为根、B 为左孩子、C 为 B 的右孩子"等多种形状。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 6 个节点大约写了 6 行 `new`（每行顺带赋值）加十来行连接 `lc`/`rc` 的代码，总共几十行以内。1000 个节点显然不现实：既写不完，也很难保证指针连对。同样的元素如果按"左小右大"组织成有序树，查找平均只要 O(log n) 的下降，而退化成单链时查找要 O(n)，差别很大；猜想要让建树和查找都高效，下一阶段会学习**二叉搜索树**（以及进一步保持平衡的平衡二叉搜索树 / AVL 树）这类有组织的查找结构。
