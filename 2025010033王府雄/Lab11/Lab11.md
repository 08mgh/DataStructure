## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归出口，按顺序逐个执行 | 无输出，仅创建、赋值、连接节点 | 无（仅局部指针变量） |
| `preorder()` | `if (root == nullptr) return;`（空树返回） | 访问根节点，在遍历左子树和右子树之前 | 无（仅递归调用栈） |
| `inorder()` | `if (root == nullptr) return;`（空树返回） | 访问根节点，在遍历左子树之后、遍历右子树之前 | 无（仅递归调用栈） |
| `postorder()` | `if (root == nullptr) return;`（空树返回） | 访问根节点，在遍历左子树和右子树之后 | 无（仅递归调用栈） |
| `levelOrder()` | `if (root == nullptr) return;`（空树返回） | 出队时访问当前节点（每次从队头取出并输出） | `std::queue<Node*>`（先进先出队列） |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种递归遍历都遵循"根、左、右"这三部分的框架，区别仅在于何时对根节点进行访问（先序：根最先；中序：左右子树之间；后序：根最后）。如果把"访问根"这句去掉，三个函数的递归结构就完全相同，都是"遍历左子树 -> 遍历右子树"，此时三个函数将完全等价，无法体现不同的遍历顺序。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 将 `lc`、`rc` 置为 `nullptr` 能明确表示"无孩子"，便于递归出口（`if (root == nullptr) return;`）和遍历时的判断（层次遍历也需判断孩子是否存在）。如果孩子指针是随机值，递归遍历会把无意义的内存地址当成节点去访问，导致非法访问、段错误甚至死循环（递归栈溢出）；层次遍历同样会向队列中加入非法指针，造成严重的运行错误。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 按"先左右子树、后根"的顺序释放，能保证在删除根节点之前，左右子树的所有节点都已经被释放，避免根节点被删除后还要通过已释放的根指针去访问子树。这个顺序对应**后序遍历**（左 -> 右 -> 根）。若先 `delete` 根再递归释放子树，根节点的指针就会被提前销毁，随后调用 `destroyTree(root->lc)` 和 `destroyTree(root->rc)` 时会通过悬空指针访问内存，导致未定义行为（很可能崩溃或访问非法内存）。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序遍历顺序为"左 -> 根 -> 右"。因此从根 `A` 开始，必须先遍历左子树 `B`。再遍历 `B` 的左子树 `D`。`D` 是叶子，没有左子树，于是先访问 `D`，所以中序序列的第一个节点是 `D`。下降路径为：`A -> lc -> B -> lc -> D`。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左的单链树（每个节点只有左孩子）：先序顺序为根-左-右 → `A B C`；中序顺序为左-根-右 → `C B A`（先遍历 `C` 的左子树空、访问 `C`、右子树空，回到 `B`，访问 `B`，再回到 `A`，访问 `A`）；后序顺序为左-右-根 → `C B A`。故**中序**和**后序**的序列相同（都是 `C B A`）。  
   > 向右的单链树（每个节点只有右孩子）：先序顺序为根-左-右 → `A B C`（左子树空，直接访问 `A`、然后遍历右子树）；中序顺序为左-根-右 → `A B C`（左子树空，访问 `A`，再遍历右子树）；后序顺序为左-右-根 → `C B A`。故**先序**和**中序**的序列相同（都是 `A B C`）。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | $O(n)$ | 每个节点恰好被访问一次，每次访问仅做常数次操作（输出），空树调用也只做常数判断，整体线性于节点数 $n$。 |
| 三种递归遍历各自的辅助空间（递归栈） | $O(h)$ | 递归栈的深度取决于树的高度 $h$。空树时 $h=0$，空间 $O(1)$（实际为 $O(0)$）；单节点树时 $h=1$，空间 $O(1)$；最坏情况下（单链树，如向左或向右的链）$h=n$，空间 $O(n)$。 |
| 层次遍历的时间 | $O(n)$ | 每个节点入队、出队各一次，每次只做常数操作，遍历全部节点，时间复杂度为 $O(n)$。 |
| 层次遍历的辅助空间（队列） | $O(w)$ | 队列最多同时存放某一层的所有节点，最坏情况是最宽的一层。空树时 $O(1)$；单节点树时 $O(1)$；完全二叉树最底层宽度最大，最坏情况下（如所有节点在同一层或退化为极宽的形状）$w$ 可达 $n$（单链树某一时刻队列中也可能有至多 1 个节点，但若形状特殊极宽则 $w=n$），一般情况下 $O(w)\le O(n)$。最坏情形：当树退化为单链时 $w=1$，队列空间 $O(1)$；当树为完全二叉树且节点都分布在最底层或接近满二叉树时 $w$ 较大，极端宽树时队列长度可达 $n$。 |
| `main` 中手动创建 6 个节点的时间 | $O(1)$（常数） | 只创建固定数量的节点（6 个），逐个 `new`、赋值、连接，操作次数与 $n$ 无关，属于常数时间。 |

说明：递归深度达到 $n$ 的形状是**单链树**（只有左孩子或只有右孩子的退化二叉树）。队列长度达到 $n$ 的形状一般出现在**极宽的二叉树**中（例如只有根节点有大量孩子，或每层节点数很大，最极端是所有 $n$ 个节点都在同一层的完全平衡的宽树，此时队列在处理该层前就可能存放整层节点，最大长度可达 $n$）。在本实验的单链树中，层次遍历每次只处理一个节点并入队其一个孩子，队列长度始终不超过 1。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归之后得到**后序遍历**（左 -> 右 -> 根）。移到两次递归中间（即"遍历左子树 -> 访问根 -> 遍历右子树"）得到**中序遍历**（左 -> 根 -> 右）。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求"从上到下、从左到右"逐层访问。队列的先进先出（FIFO）特性保证：先入队的父节点先出队，且入队时按"先左后右"的顺序，将子节点也按从左到右的顺序排列到队尾，从而实现按层、从左到右的访问顺序。  
   > 如果把队列换成栈（后进先出，LIFO），每次出栈的是最近入栈的节点。若入栈时仍按"先左后右"入栈，则右孩子会后入栈反而先出栈，导致访问顺序变成"从上到下、从右到左"；整体上更接近**深度优先**的效果（类似前序的某种变体），而不是按层次遍历的顺序。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当每个节点**最多只有一个孩子**（即单链树）或者**树的结构使得每层只有一个节点**时，先序遍历（根-左-右）和层次遍历（从上到下、从左到右）的访问顺序都是沿着这条唯一的路径逐个向下，序列可能相同。  
   > 例1：向左的单链树 `A->lc=B, B->lc=C`。先序：`A B C`，层次：`A B C`（先访问 `A`，入队其左孩子 `B`，出队 `B` 并访问，入队 `B` 的左孩子 `C`，出队 `C` 并访问，`C` 无子节点）——序列相同。  
   > 例2：只有根节点 `A`。先序：`A`，层次：`A`——序列相同。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 对于**一般的二叉树**（节点值互不相同的前提下），已知先序序列和中序序列**可以唯一确定一棵二叉树**。原理：先序的第一个元素是根，中序中根的位置可以划分左右子树，再递归确定子树结构。  
   > 若**只给先序序列**，则无法唯一确定这棵二叉树。  
   > 例子：先序序列 `A B`。可以构造：(1) `A` 只有左孩子 `B`；(2) `A` 只有右孩子 `B`。这两棵不同形状的树都具有相同的先序序列 `A B`，但中序序列分别是 `B A` 和 `A B`，因此仅凭先序序列无法唯一确定树形。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 本实验中手动创建 6 个节点共使用了约 6 行 `new`、6 行给 `data` 赋值、9 行左右孩子连接（包括显式置空）等，总计十多行代码。对于 1000 个节点的树，这种"逐个 `new`、逐个赋值、逐个连接"的方法极为繁琐、易出错且完全不可扩展，不现实。  
   > 同样的元素，树的**形态**决定了查找效率：若树形退化为单链（如链式插入），查找最坏需要 $O(n)$；若能保持树的平衡（左右子树高度尽量接近），查找最坏也能接近 $O(\log n)$。因此下一阶段很可能会学习**二叉搜索树（BST）**，以及为了防止退化而引入的**平衡二叉树**（如 AVL 树、红黑树）等结构，通过合理的插入/删除规则来维持树的平衡，从而实现高效的建树和查找。
