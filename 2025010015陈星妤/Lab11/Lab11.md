## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


要求如下：

- 三个函数都必须是**递归实现**：先处理递归出口（空树直接返回），再按各自的口诀安排"访问根"与两次递归。
- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp
void levelOrder(Node* root);
```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归，直接按三步逐个 `new` 并连结 | 将每个节点的 `data` 赋值、设置 `lc` / `rc` 连接 | 指针变量（每个节点一个 `Node*`），无栈/队列 |
| `preorder()` | `if (root == nullptr) return;` | 输出 `root->data << ' '` **之后**，先递归左子树，再递归右子树 | 递归调用栈（系统栈） |
| `inorder()` | `if (root == nullptr) return;` | 先递归左子树，**之后**输出 `root->data << ' '`，再递归右子树 | 递归调用栈（系统栈） |
| `postorder()` | `if (root == nullptr) return;` | 先递归左、右子树，**之后**输出 `root->data << ' '` | 递归调用栈（系统栈） |
| `levelOrder()` | `root == nullptr` 直接返回 | 每次从队头 `front()` 取节点并输出 `p->data << ' '`；再按先左后右将非空孩子入队 | `std::queue<Node*> q` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种遍历都要把树拆成“根、左子树、右子树”这三个部分来处理。**访问根**这件事在左子树遍历和右子树遍历之间的顺序决定是先序/中序/后序。三者的递归结构完全相同，只是输出语句插入的位置不同。如果去掉"访问根"这句话，三个函数都会变成“遍历左子树→遍历右子树”（且空树返回），对于任何二叉树得到的效果是**先序、中序、后序三个函数产生完全相同的输出序列**（实际上只剩下两次递归遍历了整棵树，但没有输出，等同于什么都没输出，只是调用顺序相同？更确切地说：若都只做递归，三个函数体一模一样，运行结果也一模一样）。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 手动建树时并非每个节点都有左右孩子（比如本次 `C` 只有右孩子）。把指针置空能明确“无孩子”这一边界，省去后续每次都要设空的重复工作，也避免忘记设置时出现野指针。若 `new` 出来时 `lc`、`rc` 是未初始化的随机值，遍历时一旦解引用这些“垃圾”指针就会走到非法内存，导致**段错误（程序崩溃）**。层次遍历也会把非法指针入队、出队再访问，从而出错。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 要释放根节点，首先必须保证根节点的左右子树已经全部释放完毕，否则一旦 `delete root`，根节点的内存被回收，再去递归访问 `root->lc`、`root->rc` 就是在访问已经释放的内存，造成**悬空指针（use-after-free）**，极易崩溃。这种“先子树，后根”的顺序正好对应**后序遍历（左→右→根）**。若先 `delete` 根，再递归释放左右子树，后续递归使用的 `root->lc`、`root->rc` 都是无效指针。

1. 中序序列的第一个节点为什么是 `D`？从根出发沿哪些指针下降找到它？

   > 中序是“左→根→右”。要得到第一个被访问的节点，必须先一路向左子树深入，直到某个节点没有左孩子为止。对本次树：`root=A` 有左孩子 `B`，先去 `B`；`B` 有左孩子 `D`，再去 `D`；`D` 没有左孩子，于是中序中第一个访问的就是 `D`。沿路径：`A->lc = B`，`B->lc = D`，`D->lc == nullptr`，故第一个节点是 `D`。

2. 考虑向左的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）：哪两种遍历的序列相同？向右的单链树中又是哪两种相同？分别说明原因。

   > 向左单链树：每个节点都只有左孩子。先序：`A,B,C`（根→左→右，其中右子树空）；中序：`C,B,A`（先一路向左到底访问 `C`，再回溯到 `B`，再回溯到 `A`，每次访问根时右子树为空）；后序：`C,B,A`（左、右（空）、根，故也是先深到底访问 `C`，再访问 `B`，再访问 `A`）。因此**中序和后序**序列相同（都是 `C B A`）。  
   > 向右单链树（`A` 右孩子 `B`，`B` 右孩子 `C`）：先序：`A,B,C`（根→左（空）→右）；中序：`A,B,C`（左空→根→右）；后序：`C,B,A`（左空、右子树后序、根）。因此**先序和中序**序列相同（都是 `A B C`）。

- 这 7 次调用中有几次是"空树直接返回"？共 4 次（第 3、4、6、7）。
- 对有 `n` 个节点的二叉树执行一次先序遍历，`preorder` 一共被调用多少次（含空树调用）？**2n+1** 次。因为每个节点对应 1 次非空调用，加上每个空指针也会触发 1 次空树调用，而在二叉树中空指针的数目是 `n+1`（对于 `n >= 0` 的二叉树），所以总调用次数 = `n + (n+1) = 2n+1`。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | Θ(n) | 每个节点恰好被访问一次（输出一次），递归调用与返回也是常数开销，故总次数与节点数成正比。空树为 Θ(0)。 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h) | 递归深度等于树的深度。最坏情况：单链树（每个节点都只有一个孩子）时 `h = n`，递归栈深度为 `n`；最好（平衡树）时 `h = O(log n)`；空树深度 0。 |
| 层次遍历的时间 | Θ(n) | 每个节点入队一次、出队一次、访问一次，均为常数操作。 |
| 层次遍历的辅助空间（队列） | O(w) | 队列中同时保存的节点最多是某一层的全部节点（通常是最宽那一层），故空间上界由最大宽度 `w` 决定。最坏：完全二叉树底层最宽可达 `n/2`，单节点树 `w=1`，空树 0。 |
| `main` 中手动创建 6 个节点的时间 | Θ(1) | 固定创建 6 个 `new`、赋值、连结操作，与 `n=6` 无变化，常数时间。 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。  
> **递归深度**：当树退化为向左或向右的**单链树**时，每一层都只有一个孩子，树高 `h = n`，递归调用链深入到最底层，系统栈深度达到 `n`。空树或单节点树 `h<=1`。  
> **队列长度**：在**完全二叉树**的最后一层（或接近满的树），同一层几乎有一半节点，最大宽度 `w = O(n)`；特别是每层节点都尽量多的形状（如完美二叉树底层）会让队列在处理该层时容纳约 `n/2` 个节点。退化为单链树时每层至多 1 个节点，队列长度始终 ≤ 1。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归**之后**：顺序变成“左→右→根”，即**后序遍历（postorder）**。  
   > 移到两次递归**中间**（左递归、访问根、右递归）：顺序变成“左→根→右”，即**中序遍历（inorder）**。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要实现“先入队的节点先被访问”（FIFO），才能保证**同一层从左到右**、**上一层先于下一层**地访问。队列正好提供 FIFO。  
   > 如果换成栈（LIFO），当处理一个节点时先把右孩子压栈再把左孩子压栈，出栈顺序就变成“左孩子后出栈、右孩子先出栈”，结果是**先访问右子树、再访问左子树**，得到的序列类似于“根→右→左”的变形（类似于先序的镜像），而不是按层次从左到右的顺序。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 只有当每个节点**至多只有一个孩子**时，先序和层次遍历的序列才会相同。  
   > 例 1：单节点树 `A` → 先序 `A`，层次 `A`，相同。  
   > 例 2：向右单链 `A->rc=B`（B 无孩子）→ 先序 `A B`，层次 `A B`，相同。  
   > 例 3：如果节点有左右两个孩子（如 `A(B,C)`），先序是 `A B C`，层次是 `A B C` 看似相同？对 `A(B,C)`：先序根→左→右 = `A,B,C`；层次根入队出队→入左B右C→出B（无孩子）→出C（无孩子） = `A,B,C`，也相同。  
   > 但更严格地说：当树是**链状**（每个节点最多一个子树分支）时二者顺序一致；当某节点有**两个孩子**时，先序严格按“左、右”的递归顺序深入左子树，层次则把左右孩子都入队并按FIFO处理。对于 `A(B,C)` 二者恰好都是 `A B C`，但对于 `A(B(D), C)`：先序 `A B D C`，层次 `A B C D`，就不同了。  
   > 简而言之：**当且仅当树中没有任何节点同时拥有左右两个孩子**（即每个节点的度 ≤ 1，退化为单链或孤立节点），先序序列与层次序列才完全相同。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > **有先序+中序**：可以唯一确定一棵二叉树。理由：先序第一个元素是根；在中序中找到根的位置，左边是左子树中序序列，右边是右子树中序序列；再根据左右子树的节点数，在先序中划分出左右子树的先序序列，递归建树。  
   > 例：先序 `[A,B,D,E,C,F]`，中序 `[D,B,E,A,C,F]` → 唯一确定本次作业的树。  
   > **只有先序序列**：一般不能唯一确定。例如先序 `[A,B,C]`，可能对应 `A(B,C)`（B左空右空，C左空右空）或 `A(B(C))`（B右空，C是B的左孩子？或者 `A(B(C))` 意味 B只有左孩子C）等等：先序相同但中序不同，树形也不同。因此只给先序无法唯一确定二叉树。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 本次手动建树：创建 6 个节点（`new Node(...)`）、赋值 `data`、设置 `lc/rc` 共约 **10~12 行**（含显式置空）。对于 1000 个节点，这种“一行一行手写连接关系”的方式极不现实，极易出错且难以维护。  
   > “同样的元素，有的树查得快、有的树查得慢”：如果树退化成单链（顺序插入且总往同一侧走），查找、插入都退化成 `O(n)`；如果树始终保持平衡（左右子树高度差不大），查找、插入都能达到 `O(log n)`。  
   > 下一阶段很可能会学习**二叉搜索树（BST）**，以及为保持平衡而引入的**平衡二叉搜索树**（如 AVL 树、红黑树）等结构。它们通过规定节点的大小关系自动组织树形（插入时按值比较决定左右），并通过旋转等手段动态维持平衡，从而让建树和查找都能高效地进行。
